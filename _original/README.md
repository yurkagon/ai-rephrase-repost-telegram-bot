# Telegram repost bot

Бот перекладає дописи українською через LangChain та публікує їх у Telegram.
Українські тексти не перефразовує. Зберігає HTML і змістовні посилання,
видаляє лише підпис джерела наприкінці допису, крім посилань на YouTube.
Підтримує текст, фото, відео та альбоми з фото й відео.

## Запуск

Потрібен Node.js 24. Версію задано в `.nvmrc`, `.node-version` та `package.json`.

```sh
nvm use
npm ci
cp .env.sample .env
npm start
```

Заповни `TELEGRAM_BOT_API_TOKEN` та `OPENAI_API_KEY` у `.env`.
Старий `OPEN_API_SECRET_KEY` також підтримується; `OPENAI_API_KEY` має пріоритет.
`LLM_MODEL` задає модель, стандартна — `gpt-6-luna`.
`TARGET_CHANNEL` задає канал призначення (`@username` або числовий ID),
за замовчуванням — `@test_yuragon`. Бот має бути адміністратором каналів.
Дописи з каналу призначення повторно не копіюються.

## Структура

```text
app/
  index.ts             # конфігурація, створення залежностей і запуск
  config.ts            # перевірка конфігурації
  app.ts               # зв'язок Telegram з перекладом
  ai/
    model.ts           # фабрика LangChain-моделі
    TextRewriter.ts    # structured output, перевірка та метадані виконання
    prompt.ts          # системний промпт у Git
  libs/
    TelegramBot.ts     # публікація тексту й медіа
```

Модель створюється один раз і передається в `TextRewriter` через конструктор.
Telegram використовує `rewriteTelegramHTML(text): Promise<string>` і не залежить
від AI-схеми. Схема Zod описує єдине поле `{ html: string }`; виклик
`withStructuredOutput()` використовує `jsonSchema`, `strict: true`, `includeRaw: true`.

OpenAI працює через Responses API з `reasoning.effort: "low"`, без `temperature`.
Таймаут кожного запиту — 30 секунд; LangChain робить не більше двох повторів
тимчасових транспортних помилок. Відмови, помилки схеми, некоректний JSON,
порожні та незавершені відповіді не спричиняють повторної генерації.

При помилці допис не публікується. Для альбому всі підписи готуються до його
відправлення; помилка будь-якого підпису блокує весь альбом. Оригінал не
використовується як запасний результат. Медіа без підпису не потребує AI-запиту.
Альбоми збираються після однієї секунди без нових елементів.

У консоль записуються модель, тривалість, токени та результат AI-виклику.
Помилки Telegram містять ідентифікатори та тип помилки. Повні дописи,
відповіді моделі та ключі не логуються. Помилка запуску завершує процес
із ненульовим кодом.

## Заміна провайдера

Зміни `createLanguageModel()` у `app/ai/model.ts`, щоб вона повертала
відповідну LangChain-модель, і передай її в `TextRewriter`.
Провайдер має підтримувати системні інструкції та `withStructuredOutput()`
з цією схемою і повертати raw-метадані завершення. Провайдер без structured
output завершується помилкою; автоматичного переходу до довільного тексту немає.

## Перевірки

```sh
npm test
npm run typecheck
```

Тести використовують локальні HTTP-відповіді та моделі-заглушки.
Перевіряють контракт AI, параметри запиту, помилки й відсутність публікації
при невдалому перекладі. TypeScript працює в режимі `strict`.

Structured output перевіряє форму відповіді, але не гарантує правильність
перекладу чи валідність Telegram HTML. Evals відкладено до наступного кроку;
якість перекладу та доступ до нової моделі потребують окремої перевірки.
Стан альбомів зберігається в пам'яті до перезапуску: стійку дедуплікацію та
повторну доставку можна додати разом зі сховищем. PostgreSQL, Web і NestJS
у цьому рефакторингу не додаються.
